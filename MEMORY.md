## Refinements (deferred to Phase 2/3 polish)

### Project-grouping in LLM extraction
- In `resume_clean.txt`, the `PROJECTS:` section uses group headers (`Open Source Contributions`, `Personal Projects`) each containing 2 bullet items. The LLM treats each header as a single project name and collapses the bullets into one description → **4 real project bullets become 2 entries** (grouping is lossy, no bullet text dropped).
- **Candidate fix (rejected for Phase 1):** prompt instruction to expand nested project groups into individual projects + preserve figures like "400 stars".
- **Status:** logged as polish item — revisit in Phase 2/3 if the skill engine needs granular project data.

### Short project descriptions in resume_tabular
- Tabular project lines like `Ledger visualization dashboard — React + D3 + WebSockets, live metrics.` parse with a thin `description` ("live metrics.") because the dash splits name vs techs vs description and the description is trivially short by design. On the rate-limiter line, `400 stars` was dropped from the description.
- **Status:** cosmetic/negligible; logged for prompt refinement in Phase 2/3.

## Known Limitations (deferred to Phase 2)

### LLM extraction cost / availability
- Experience/education/projects parsing now runs through the LLM orchestrator (`feature="resume_parsing"`, `openai/gpt-4o-mini`) via `backend/services/resume_ai.py`. This incurs real token cost and requires a working `OPENROUTER_API_KEY`.
- If the LLM call fails or returns empty, it degrades gracefully to the improved regex fallback (`backend/services/resume_parser.py`) — uploads never 500.
- Skills remain regex-based (proven reliable: 25/13/1).
- Each successful LLM parse writes a row to `llm_usage_log` (Phase 6 requirement, now implemented).

### GitHub language aggregation via API
- Languages are aggregated from each repo's `languages_url` (bytes per language). Empty-repo/edge cases and rate-limit throttling can yield incomplete data.
- Root-caused and fixed the double-`/languages` bug (was 404 → empty). See `backend/services/github.py::_fetch_languages`.

### Next.js proxy upload body size
- `next dev` proxy buffers request bodies and truncates at a limit. Configured `experimental.middlewareClientMaxBodySize: "12mb"` so the backend's own 10MB check responds (`400 "File size must be under 10MB"`) instead of a generic 500.
- This is a dev-server/single-process concern; revisit for production deployment sizing.

### Log redaction
- uvicorn access logs echo query strings. Added `RedactSensitiveQueryParams` filter (`backend/main.py`) that blanks `code`/`state`/token params. Audit for any new endpoints logging sensitive values before shipping.
